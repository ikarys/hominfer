Run local AI models like home services.

hominfer starts, stops and watches your models from a browser tab, whatever engine runs them. Linux or WSL2, NVIDIA or AMD.

curl -LsSf https://raw.githubusercontent.com/ikarys/hominfer/main/install.sh | bash

Then run hominfer and open http://127.0.0.1:8090.

MIT licence. Python stdlib, psutil and huggingface_hub; no build step.

Any model, with the engine you choose.

llama.cpp, vLLM, Ninfer or a command-line server released last week: an engine is a JSON block in a file, not code. hominfer fills in the port, the model file and your options, then starts it, checks its health endpoint and keeps it in view.

"llama.cpp": {
  "command": ["~/llama.cpp/build/bin/llama-server", "-m", "{file}",
              "--port", "{port}", "-c", "{ctx}", "-np", "{parallel}"],
  "health": "/health",
  "endpoint": "/v1"
}

An engine entry from engines.example.json, shortened.

One card per model: start, stop, profile.

Each model gets a card with live VRAM, RAM, CPU and GPU load, its local and LAN endpoints ready to copy, and the engine's own counters. Context size, parallel sessions, vision, CPU or GPU are saved as profiles and switched in one click.

See how your models are really used.

Up time, busy time, peak requests and how many sessions run at once, per model and per engine, over 24 hours, 7, 30 or 90 days, or any range. The numbers you need to size context and parallel sessions.

Check it fits before you download.

Paste a Hugging Face repository. Every variant gets a verdict from your GPU, your installed engines and your free disk: fits on the GPU, needs a partial offload, doesn't fit, or needs an engine you don't have yet.

A missing engine installs from the page, with no sudo: the CUDA toolkit comes from NVIDIA's pip wheels, and AMD and Intel get a Vulkan build. Missing system tools are listed before anything starts.

It behaves like a service.

Starts at boot
The installer can set up a systemd service, reachable from your LAN with --service --lan.
Restarts what crashes
An engine that dies or stops answering is restarted, at most three times an hour.
Keeps the machine awake
The PC does not go to sleep while a model is loaded.
Logs everything
The live engine log, the exact command line, and a record of starts, crashes and warnings.
Speaks OpenAI
Every running model shows an OpenAI-compatible endpoint, for any client on your network.
Cleans up
The library shows what each model takes on disk, and removes what you no longer use.

There is no login. Keep hominfer on a network you trust.

Why not Ollama or LM Studio?

I went from Ollama to LM Studio to Unsloth Studio, chasing speed. Then a command-line engine doubled it on the same GPU, and none of those apps could run it. hominfer started as a single Start button for it, and grew from there.

The fastest engine for your GPU is often one those apps don't run: a fresh llama.cpp build, vLLM, a new project that only has a command line. hominfer runs whichever you pick, with its own options, from any browser at home.
